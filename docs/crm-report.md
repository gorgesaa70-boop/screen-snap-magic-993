# تقرير تطوير الـ CRM متعدد الشركات (المراحل 1–6)

آخر تحديث: 2026-10-12

## الحالة قبل التطوير (المرحلة 1)
كان موجود: حساب لكل شركة (وساطة / مطور / مكتب) وفريقها بأدوار (صاحب الحساب / مدير / مبيعات)، عزل بيانات في قاعدة البيانات (RLS)، ملف عميل كامل برقم ثابت ومصدر أصلي وإحالة أولى، قواعد توزيع بالأولوية والدور، سجل إسناد، سجل تدقيق، تقارير، صفقات وعمولات بمراجعة الإدارة. الناقص كان: النقل التلقائي، تعريف دقيق للتواصل الفعلي، تفاصيل سجل الإسناد، عرض المهلة، ربط العميل بالمشروع، رفع العملاء من Excel.

## القرارات المعتمدة
| البند | القرار |
|---|---|
| حساب الـ 60 دقيقة | دقايق شغل (ساعات العمل من الإعدادات، افتراضي 9–21 بتوقيت القاهرة) |
| اللي بيوقف المهلة | نتيجة «رد واتكلمنا» أو «طلب نكلمه تاني»، أو نقل العميل لمرحلة «تم التواصل» أو بعدها |
| اللي ما بيوقفهاش | الضغط على اتصال/واتساب لوحده، «ما ردش»، الملاحظات، مواعيد المتابعة |
| الرقم الغلط | بيروح لطابور الإدارة للمراجعة بدل شركة تانية |
| أقصى عدد شركات | 3 (قابل للتعديل من 1 لـ 10)، بعدها طابور الإدارة |
| الإسناد اليدوي | عليه مهلة برضه |
| برّه النقل | طلبات الاستثمار وعروض الملاك |

## اللي اتعمل
**المرحلة 2 — العزل:** العزل موجود في قاعدة البيانات؛ اتضافت اختبارات: الشركة اللي العميل اتنقل منها ما بتشوفهوش ولا سجله، وما تقدرش تعدّل عليه أو تضيف نشاط، والشركات ما بتقراش سجل الإسناد.

**المرحلة 3 — إدارة العملاء** (`20261012900000_crm-leads.sql`):
- نتيجة التواصل على المكالمة/الواتساب (`lead_activities.outcome`)، ووقت وصاحب ونوع أول تواصل فعلي (`leads.first_response_at/by/outcome`).
- ربط العميل بالمشروع والوحدة (`leads.project_id / project_unit_id`).
- سجل الإسناد بقى فترات: المصدر (توزيع / يدوي / نقل تلقائي / نظام)، المهلة، نهاية الفترة وسببها، نتيجة التواصل، ملاحظة.
- رفع العملاء من Excel (الإدارة وفريق فاليو عقار) مع كشف التكرار من غير دمج.

**المرحلة 4 — النقل التلقائي** (`20261013000000_crm-transfer.sql`):
- `leads.transfer_deadline_at` بتتحسب عند كل إسناد لشركة بـ `add_work_minutes()`.
- `run_lead_transfers()` في السيرفر: بتقفل العملاء المستحقين (SKIP LOCKED) وتراجعهم وتنقلهم بتعديل مشروط — مستحيل نقل مرتين أو شركتين في نفس الوقت. الشركة التالية من قواعد التوزيع، نشطة، ومش استلمت العميل قبل كده. بعد أقصى عدد أو مفيش شركة أو رقم غلط ← طابور الإدارة (`admin_queue_at/reason`) + إشعار.
- تنبيه للشركة لما يفضل ربع المهلة؛ إشعار للشركة القديمة والجديدة.
- كل تشغيل متسجل في `job_runs`؛ الأخطاء في `app_errors`. متربطة بالمهمة المجدولة `whatsapp-dispatch`.
- الإدارة تقفل النقل أو تغيّر المدة وساعات العمل وأقصى عدد شركات من «قواعد التوزيع».

**المرحلة 5 — الواجهات والتقارير:**
- عداد المهلة المتبقية (بدقايق الشغل) على كارت العميل، والجدول، وصفحة العميل، ولوحة الوسيط — للعرض بس، والقرار في السيرفر.
- أزرار نتيجة التواصل لحد أول تواصل فعلي.
- فلاتر: مستنيين أول تواصل / المهلة قربت تخلص / طابور الإدارة.
- تقارير: اتواصلوا فعليًا، ما ردوش، اتنقلوا بسبب المهلة، متوسط عدد الشركات لكل عميل، طابور الإدارة، وعمود «اتنقلوا منها» لكل شركة. متوسط وقت أول تواصل بقى من التواصل الفعلي بس.
